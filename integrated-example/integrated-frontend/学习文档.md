# 学习文档：integrated-frontend（前端页面模块）

> 位置：`integrated-example/integrated-frontend` —— 整合示例的**演示入口**：
> 三个 Thymeleaf 页面（下单 / RocketMQ 点赞 / Sentinel 限流），让整套微服务"看得见摸得着"。

---

## 一、这个模块做了什么

整个模块只有 2 个 Java 文件 + 3 个 HTML 模板，不含任何业务逻辑：

| 文件 | 作用 |
|---|---|
| `FrontendApplication` | 启动类（spring-boot-starter-web + thymeleaf） |
| `IntegrationController` | `@Controller`（非 RestController），做 URL → 模板名映射 |
| `templates/order.html` | 下单页：填参数下单、查库存/余额，观察 Seata 事务与回滚 |
| `templates/rocketmq.html` | 点赞页：点"点赞"发消息、查点赞数，观察 MQ 削峰与延迟 |
| `templates/sentinel.html` | 限流页：快速点赞，观察 Sentinel 网关限流提示 |

### 页面与服务的关系

```
浏览器 ──► /order /rocketmq /sentinel        (本模块渲染页面, 纯 HTML)
       ──► :30010/order/create 等            (页面按钮 → 网关 → 各微服务)
```

即：页面由本服务出，**真正的请求全部走网关**打到后端微服务 —— 前端服务本身不掺和业务。

### `@Controller` vs `@RestController`
返回值 `"order"` 是模板名 → Thymeleaf 渲染 `templates/order.html`；而 RestController 返回的字符串是 JSON。

## 二、需要学习的知识点

1. **Thymeleaf 模板基础**：`@Controller` + 模板名映射、静态资源、模板内取值语法（页面本身用了 ajax+js 调网关）。
2. **页面与网关的关系**：前端所有动态请求统一走网关端口 30010 —— 印证"网关是唯一流量入口"。
3. **BFF/演示层定位**：为什么页面独立成服务（独立部署、不拖累业务服务、可换成 Vue/React 静态站 + Nginx）。
4. **演示页设计思路**（值得借鉴）：每个中间件能力配一个可操作的页面 + 可观察的数据变化，比看文档高效得多。

## 三、学习目的

- 给整套后端实验提供**可视化操作台**——学 Seata/MQ/限流时用它点一点，胜过 curl 十次；
- 理解服务端渲染（SSR）与前后端分离架构的差异与取舍；
- 学习示例工程"如何把抽象中间件能力做成可感知的演示"的方法论。

## 四、以后怎么用

1. 本地/演示环境快速搭建可视化验证页，直接复用本模块模板改改即可。
2. 生产前端主流是独立前端工程（Vue/React + Nginx/CDN），后端只出 REST 接口 —— 本模块可视为"轻量 BFF"形态。
3. 内部工具/管理后台也常用 Thymeleaf 这套"一个服务搞定页面+接口"的形态，快速出活。
