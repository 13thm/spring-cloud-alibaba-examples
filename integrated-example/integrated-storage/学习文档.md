# 学习文档：integrated-storage（库存服务）

> 位置：`integrated-example/integrated-storage`（端口 8011）—— 下单链路的
> **Seata AT 模式分支事务参与者（RM）**，负责扣减商品库存。

---

## 一、这个模块做了什么

标准三层微服务（Controller → Service → Mapper），操作独立的 `integrated_storage` 库：

| 文件 | 作用 |
|---|---|
| `StorageServiceApplication` | 启动类 |
| `StorageController` | `POST /storage/reduce-stock` 扣库存（被订单 Feign 调）；`GET /storage/?code=` 查库存 |
| `StorageDTO` | 扣减请求（commodityCode + count） |
| `StorageService(Impl)` | **核心**：`@Transactional` 分支事务 + XID 日志 + 库存校验 |
| `StorageMapper` | MyBatis 注解 SQL：查库存 / 扣库存 |
| `application.yaml` | Nacos 双中心 + Seata 客户端配置 |
| Nacos: integrated-storage.yaml | 只覆盖数据源 url（分库） |
| SQL: storage 表 + **undo_log 表** | 初始库存 100 件；undo_log 供 Seata 回滚 |

### 在 Seata 全局事务中的位置

```
订单服务(TM, @GlobalTransactional)
   │ Feign + XID 透传
   ▼
本服务 reduceStock() ← @Transactional 本地事务 = 全局事务的"分支①"
   ① UPDATE 前后 Seata 自动把数据前后镜像写入 undo_log
   ② 分支注册/状态上报由 Seata 数据源代理自动完成（业务代码无感知）
   ③ 全局回滚时：按 undo_log 反向补偿，库存自动加回去
```

### 演示剧本中的角色
初始库存 100 件、单价 2 元。买 1 件成功；余额耗尽后再下单时，**本服务的库存已经扣掉**，
随后全局回滚把库存补回 100 —— 观察 storage 表数据"先变 99 再变回 100"就是 AT 模式最直观的证据。

## 二、需要学习的知识点

1. **Seata AT 模式分支事务写法**（本模块精华）
   - 只需 `@Transactional` + Seata 依赖 + undo_log 表，**业务代码零侵入**；
   - 一阶段：本地事务提交时同时提交 undo_log（同库同事务，原子）；
   - 二阶段回滚：按 undo_log 反 SQL 补偿；二阶段提交：异步删 undo_log。
2. **XID 传播验证**：`RootContext.getXID()` 打日志，与订单服务日志比对一致性。
3. **Nacos 分层配置**：共享 `datasource-config.yaml`（账号/密码/驱动）+ 专属 yaml（只覆盖 url）——"公共+覆盖"的配置复用模式。
4. **MyBatis 注解 SQL**：`@Select/@Update/@Param`，以及 `update_count == 0` 的乐观校验思想。
5. **防御式写库**：SQL 层防扣成负数（对比 AccountMapper 的 `money >= price` 条件，本模块靠前置校验）。

## 三、学习目的

- 掌握 **RM（Resource Manager）** 角色的标准写法：它是分布式事务里数量最多的参与者，"每个微服务都是这样接 Seata 的"；
- 理解 AT 模式"自动补偿"的底层依赖（数据源代理 + undo_log），从而明白为什么**每个业务库都要建 undo_log 表**；
- 学会分库 + 共享配置的数据源治理方式。

## 四、以后怎么用

1. **接入姿势（三步，任何存量服务通用）**：
   - pom 加 `spring-cloud-starter-alibaba-seata`；
   - 业务库执行 undo_log 建表 SQL；
   - yaml 加 `seata.application-id / tx-service-group / vgroup-mapping / grouplist` 四段配置。
2. **TC 地址进阶**：示例用 `grouplist` 直连 TC，生产改用 TC 注册到 Nacos，客户端按 `vgroup-mapping` 自动寻址。
3. **并发进阶**：高并发扣库存可在 SQL 加 `AND count >= #{count}`（参考账户模块）或改用 Redis 预扣。
4. **排查工具**：回滚异常时查 `undo_log`、TC 控制台的全局事务记录，用 XID 串联全链路日志。
