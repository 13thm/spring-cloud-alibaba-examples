# 学习文档：integrated-order（订单服务）★ 全局事务核心

> 位置：`integrated-example/integrated-order`（端口 8013）—— 下单链路的
> **Seata TM（全局事务发起者）+ 服务编排者**，整个分布式事务示例最核心的模块。

---

## 一、这个模块做了什么

通过 Feign 编排"扣库存 → 扣余额 → 存订单"三个动作，并用 `@GlobalTransactional` 把它们包裹成一个**跨三个库的全局事务**：

| 文件 | 作用 |
|---|---|
| `OrderServiceApplication` | 启动类，`@EnableFeignClients` 开启 Feign 扫描 |
| `OrderController` | `POST /order/create` 下单入口（网关路由 `placeOrder` 指向这里） |
| `OrderService(Impl)` | ★核心：`@GlobalTransactional` + 三步编排 + code 判断 |
| `AccountServiceFeignClient` | Feign 声明式调用账户服务 |
| `StorageServiceFeignClient` | Feign 声明式调用库存服务 |
| `Order` / `AccountDTO` / `StorageDTO` | 实体与请求 DTO（下游 DTO 的本地副本） |
| `OrderMapper` | 插入订单，`@Options` 回填自增 id |
| `application.yaml` | Nacos + Seata 配置（身兼 TM 和 RM 两职） |

### @GlobalTransactional 完整时序（必背）

```
OrderServiceImpl.createOrder()  ← AOP 拦截开启全局事务
 ① TM → TC: 开启全局事务, 取得 XID
 ② Feign→库存(带XID头): 分支①注册, 库存 100→99, 写 undo_log
 ③ Feign→账户(带XID头): 分支②注册
 ④ 本地插订单(同数据源代理): 分支③注册
 ── 全部成功 ──► TM→TC 全局提交, 各分支异步删 undo_log
 ── 任一步抛异常 ──► TM→TC 全局回滚, 各分支按 undo_log 反向补偿(库存 99→100)
```

### 最容易被忽略的细节（本模块的精髓）

Feign 调用下游"业务失败"时拿到的是 **HTTP 200 + code=2003** 的正常响应，
异常不会自动抛出！所以必须手动判断：

```java
Integer storageCode = storageService.reduceStock(storageDTO).getCode();
if (storageCode.equals(COMMON_FAILED.getCode())) {   // 2003
    throw new BusinessException("stock not enough"); // ★ 不抛 = 不回滚！
}
```

这是声明式 HTTP 调用与本地方法调用的本质差异，也是生产事故高发点。

## 二、需要学习的知识点

1. **Seata 三角色模型**：TM（发起点，本模块）/ RM（分支参与者，库存账户）/ TC（协调者，seata-server:8091）—— 本模块身兼 TM+RM。
2. **`@GlobalTransactional` 注解语义**：rollbackFor 默认规则、与本地 `@Transactional` 的嵌套关系。
3. **XID 跨服务传播机制**：Seata 对 Feign/RestTemplate 的请求头拦截器自动携带 XID，下游用 `RootContext.getXID()` 验证。
4. **OpenFeign 声明式调用全链路**：`@FeignClient(name=服务名)` → Nacos 发现 → 负载均衡选址 → HTTP 序列化/反序列化；接口签名必须与 Provider 完全一致。
5. **服务编排模式**：Saga 式顺序调用 + 失败即抛异常，对比"全部成功再统一确认"的写法差异。
6. **MyBatis 主键回填**：`@Options(useGeneratedKeys=true)` 让 INSERT 后拿到自增 id。

## 三、学习目的

- 学会**在"哪一个服务"上开全局事务**：编排入口 = 事务边界，这是架构设计决策而不只是代码问题；
- 吃透"业务失败码 → 异常 → 回滚"的信号转换链，避免"加了注解却回滚不了"的假分布式事务；
- 掌握 Feign 的标准用法，它是 Spring Cloud 服务间调用的绝对主流。

## 四、以后怎么用

1. **通用公式**：跨库写操作的服务编排方法上打 `@GlobalTransactional`，下游每个库建 undo_log，失败一律抛异常。
2. **注意事项**：
   - 全局事务方法内尽量不做 RPC 重试超长操作（拉长事务持有时间）；
   - 下游只返回失败码的场景必须显式判断 code（抄本模块写法）；
   - 高并发场景评估 AT 行锁冲突，必要时换 TCC/Saga 模式。
3. **扩展练习方向**：给 Feign 加 fallback 降级；把订单落库改成 MQ 异步化（与点赞场景融合）。
4. **排障口诀**：回滚没生效 → 查 XID 是否传播 → 查 code 判断是否遗漏 → 查 undo_log 表是否存在。
