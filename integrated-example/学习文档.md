# 学习文档总览：integrated-example（Spring Cloud Alibaba 综合整合示例）

> 这是 SCA 官方的**集大成示例**：一条命令（docker-compose/helm）拉起全套环境，
> 用两个贴近真实的业务场景，把 Nacos、Gateway、Sentinel、Seata、RocketMQ
> 五大组件"串成一串"综合演练 —— 各子模块目录下有对应详细学习文档。

---

## 一、整体架构：一次请求的全景图

```
                          ┌─────────────────┐
        浏览器/前端 ──────►│  Gateway :30010 │◄── Sentinel 限流(5 QPS) / 动态路由(Nacos)
                          └────────┬────────┘
              ┌──────────┬─────────┼──────────┬──────────┐
              ▼          ▼         ▼          ▼          ▼
        ┌──────────┐┌─────────┐┌────────┐┌──────────┐┌──────────┐
        │ storage  ││ account ││ order  ││ provider ││ consumer │
        │ :8011 RM ││:8012 RM ││:8013 TM││ :8015 生产││ :8014 消费│
        └────┬─────┘└────┬────┘└───┬────┘└────┬─────┘└────┬─────┘
             ▼           ▼         │ Feign+XID  │消息      │按速率拉取
        integrated_storage/account/order 库     ▼          ▼
        (每库含 undo_log)              RocketMQ(PRAISE-TOPIC-01) → praise 库

   注册/配置: Nacos :8848 (group=integrated-example)
   事务协调:  Seata TC :8091        数据库: MySQL(integrated-mysql)
```

## 二、两大业务场景与组件分工

| 场景 | 链路 | 演示的组件能力 |
|---|---|---|
| **用户下单** | order →(Feign)→ storage + account → 落订单 | **Seata AT 分布式事务**：余额不足触发全局回滚，库存自动补偿 |
| **商品点赞** | provider →(MQ)→ consumer → 落库 | **RocketMQ 削峰填谷**(4秒/4条的消费阀门) + **Sentinel 网关限流**(5 QPS) |
| 两个场景共用 | 网关路由 / 服务发现 / 配置管理 | **Gateway 动态路由 + Nacos 注册&配置中心** |

## 四、配套基础设施目录（非代码模块，但部署必读）

| 目录 | 内容 | 学习点 |
|---|---|---|
| `config-init/config/` | 推送到 Nacos 的 7 份 yaml：网关路由、MQ 绑定、共享数据源、各服务 url 覆盖 | **配置分层**：本地 application.yaml(端口/地址) + Nacos 专属配置(url 覆盖) + Nacos 共享配置(账号密码) 三层叠加 |
| `config-init/sql/init.sql` | 建库建表 + 初始数据 + **3 个业务库的 undo_log 表** | 分库设计；初始数据是"剧本"（库存100/余额3/单价2 → 第二单必回滚） |
| `config-init/scripts/` | nacos-config-quick.sh 一键导入配置脚本 | 批量导入 Nacos 配置的 CLI 姿势 |
| `docker-compose/` | 环境编排(env.yml: Nacos/MySQL/Seata/RocketMQ) + 服务编排(service.yml) | 容器化整体交付；服务名即主机名(nacos-server:8848 等)的由来 |
| `helm-chart/` | K8s Helm Chart 全套模板 | 云原生部署形态 |

## 五、建议学习路径（4 步）

1. **跑通环境**：按 `docs/zh/docker-compose-deploy-zh.md` 起全套，浏览三个前端页面；
2. **逐模块读代码**（已全部加详细中文注释）：
   common → gateway → storage → account → order（先理解 Seata 链路）
   → provider → consumer（再理解 MQ 链路）；
3. **做实验**：各模块学习文档末尾均有"动手验证清单"，重点完成
   ① 余额不足看库存回滚 ② 狂点点赞看限流 ③ 观察 MQ 消费延迟；
4. **横向总结**：对比"限流 vs 削峰"两种大流量治理思路；对比"本地事务 vs 全局事务"写法差异。

## 六、核心知识点速记（面试向）

- **Seata AT**：TM 开事务发 XID → Feign 透传 → 各 RM 本地提交+写 undo_log → 失败按镜像反向补偿；每个业务库必须有 undo_log；
- **假回滚陷阱**：Feign 拿到 HTTP 200 + code 2003 不抛异常，必须手动判 code 抛异常才会回滚；
- **动态路由**：Gateway 路由存 Nacos，`spring.config.import` 导入，改配置即生效；
- **Sentinel 网关三件套**：GatewayFilter(入口) + BlockExceptionHandler(出口) + GatewayRuleManager(规则)，按路由 ID 限流；
- **Stream 函数式模型**：发送用 `StreamBridge.send(绑定名,msg)`；消费定义 `Consumer` Bean + `function.definition` 声明，通道名 `函数名-in-0`；
- **削峰阀门**：`pullInterval × pullBatchSize` 决定下游数据库的真实写入速率。
