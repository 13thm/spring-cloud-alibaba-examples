# Sentinel RestTemplate Example — 学习分析文档

> 本文档面向 Spring Cloud Alibaba 初学者。本模块演示 **RestTemplate 调用 + Sentinel 防护**:
> 给 RestTemplate 加一个 `@SentinelRestTemplate` 注解,出站请求就自动纳入限流/熔断统计。
> 它与 openfeign 模块是**孪生兄弟**(同样的 httpbin.org、同样的三条规则、同样的三个实验),
> 建议对照学习,重点体会"两种客户端,同一套 Sentinel"。

## 1. 项目定位:它是什么?

| 维度 | 说明 |
|------|------|
| 角色 | 服务消费者(用 RestTemplate 手写 URL 调用 httpbin.org) |
| 防护方式 | `@SentinelRestTemplate` 注解 → 出站请求自动成为 Sentinel 资源 |
| 演示的三种策略 | QPS 限流 / 异常数熔断 / 慢调用比例熔断(与 openfeign 完全一致) |
| 规则加载方式 | 代码方式(`@PostConstruct` + Manager.loadRules) |
| 降级方式 | 注解默认兜底(本模块未自定义 blockHandler,对比 core 模块) |

**与 openfeign 模块的差异一览**(学习重点):

| | openfeign | resttemplate(本模块) |
|---|-----------|------------------------|
| 客户端 | Feign 声明式接口 | RestTemplate 手写 URL |
| 开启方式 | `feign.sentinel.enabled: true` | `@SentinelRestTemplate` 注解在 Bean 上 |
| 资源名 | `GET:https://httpbin.org/get` | `GET:https://httpbin.org/get`(**完全一样!**) |
| 降级 | fallbackFactory(拿到 Throwable) | blockHandler(可自定义,本模块用默认) |

> 💡 资源名一致意味着:**换客户端不换规则**——这就是 Sentinel"资源抽象"的价值。

## 3. 核心概念:@SentinelRestTemplate 做了什么

```java
@Bean
@SentinelRestTemplate          // ← 全部魔法在这一行
public RestTemplate restTemplate() { return new RestTemplate(); }
```

Sentinel 会给这个 RestTemplate 织入一个拦截器(装饰器模式),每次调用:

```
restTemplate.getForObject("https://httpbin.org/get", String.class)
   ↓ 拦截器截获
① 拼资源名: 方法(GET) + : + URL(https://httpbin.org/get) → "GET:https://httpbin.org/get"
   (默认只到 host,不含 path;可用 urlCleaner 自定义,见进阶练习)
② 进入 Sentinel Slot 链:统计 + 查规则
   └─ 被拦 → 执行 blockHandler(默认兜底 / core 模块演示了自定义)
③ 通过 → 发真实 HTTP 请求
```

**注解可用属性一览**(本模块只用默认):

| 属性 | 作用 |
|------|------|
| `blockHandler` / `blockHandlerClass` | **限流/熔断被拦**时的处理方法(core 模块的 ExceptionUtil 就是这个) |
| `fallback` / `fallbackClass` | 请求本身**异常**(超时/404)时的处理 |
| `urlCleaner` / `urlCleanerClass` | 清洗资源名(合并路径统计,nacos-consumer 模块有完整例子) |
| 异常比例熔断相关 | `degradeGrade`、`degradeCount` 等可直接在注解上配熔断 |

## 4. 代码逐文件精读

### 4.1 RestTemplateConfiguration — 唯一的新知识

📄 `configuration/RestTemplateConfiguration.java`:

```java
@Configuration
public class RestTemplateConfiguration {

	@LoadBalanced                 // ① 负载均衡注解(见坑 3 的解释)
	@Bean
	@SentinelRestTemplate         // ② Sentinel 出站防护
	public RestTemplate restTemplate() {
		return new RestTemplate();
	}
}
```

### 4.2 TestController — 三个实验入口

📄 `controller/TestController.java`:

```java
@RestController
public class TestController {

	@Autowired
	RestTemplate restTemplate;                    // 上面那个被保护的 Bean

	@GetMapping("/exp")
	public String exp() { return restTemplate.getForObject("https://httpbin.org/status/500", String.class); }

	@GetMapping("/rt")
	public String rt()  { return restTemplate.getForObject("https://httpbin.org/delay/3", String.class); }

	@GetMapping("/get")
	public String get() { return restTemplate.getForObject("https://httpbin.org/get", String.class); }
}
```

### 4.3 SentinelRulesConfiguration — 与 openfeign 完全同款

内容与 openfeign 模块一字不差(三条规则:限流 / 异常数熔断 / 慢调用熔断),
详见 [openfeign 模块第 5 节](../sentinel-openfeign-example/学习分析.md#5-规则加载sentinelrulesconfiguration-逐行精读)。
**唯一值得再想一遍的点**:规则里的资源名 `GET:https://httpbin.org/get` 同时适配
Feign 和 RestTemplate 两种客户端——Sentinel 只认资源名,不关心客户端是谁。

### 4.4 RestTemplateApplicationTest — 为什么有个 @Disabled 测试

```java
@Disabled("For debugging")
public class RestTemplateApplicationTest {
	@Test
	public void runWithSpringAotModeAfterProcessAot() throws Exception {
		System.setProperty("spring.aot.enabled", "true");     // AOT 模式
		RestTemplateApplication.main(new String[0]);          // 直接拉起应用
	}
}
```
这是给 **GraalVM Native Image / AOT** 冒烟测试用的(需先 `mvn clean install -Pnative`),
平时禁用。知道它不是普通单测即可。

## 5. 规则与资源名(与 openfeign 模块对照)

| 规则(代码加载) | 资源名 | 策略 | 效果 |
|------------------|--------|------|------|
| FlowRule | `GET:https://httpbin.org/get` | QPS=1,快速失败 | 1 秒第 2 次 → 默认兜底文案 |
| DegradeRule 1 | `GET:https://httpbin.org/status/500` | 异常数≥1,minRequestAmount=1,熔断 30s | 1 次异常即熔断 |
| DegradeRule 2 | `GET:https://httpbin.org/delay/3` | 慢调用 RT>1ms,比例>10%,熔断 30s | 一次慢请求后熔断 |

被拦时的**默认兜底**:本模块没有自定义 blockHandler,Sentinel 返回内置的 429 文案
(`This request is blocked by Sentinel (flow limiting)`)。想要"custom block info"那样的自定义响应,
照抄 core 模块的 `ExceptionUtil` + `blockHandler` 属性即可。

## 6. 一次限流请求的流程图

```
浏览器 → GET http://localhost:18088/get
      │
      ▼
TestController.get() → restTemplate.getForObject("https://httpbin.org/get")
      │
      ▼
Sentinel 拦截器(@SentinelRestTemplate 织入)
  资源名: GET:https://httpbin.org/get
      │
      ▼
FlowSlot: 1 秒窗口内 QPS 是否已达 1?
      │
      ├─ 未达 → 放行 → 真实 HTTP 请求 → 返回 httpbin JSON ✅
      │
      └─ 已达 → 抛 FlowException → blockHandler(默认)
                      │
                      ▼
              429 + "This request is blocked by Sentinel..." ❌
              (HTTP 请求根本没有发出去!)
```

## 7. 如何运行与实验设计

### 7.1 前置
1. (推荐)Sentinel 控制台 8080
2. 外网可达 httpbin.org
3. 修坑 1 后启动,端口 **18088**

### 7.2 实验清单(与 openfeign 模块一一对应)

```bash
# 实验 1:QPS 限流
curl http://localhost:18088/get          # 正常返回 httpbin JSON
curl http://localhost:18088/get          # → 429 默认兜底文案(限流)

# 实验 2:异常数熔断
curl http://localhost:18088/exp          # 真调用 → httpbin 500 → FeignException 等价的 RestClientException
curl http://localhost:18088/exp          # 熔断打开 → 秒回兜底文案,30 秒内持续

# 实验 3:慢调用熔断
curl http://localhost:18088/rt           # 第一次 ~3 秒(真调用+异常/慢)
curl http://localhost:18088/rt           # 熔断打开 → 秒回兜底文案
```

### 7.3 对照实验(强烈建议)
同一天把 openfeign(18087)和本模块(18088)都跑起来,各做一遍三个实验,记录:
- 兜底文案差异(fallbackFactory 文案 vs 429 默认文案)
- 控制台"簇点链路"里资源名完全一致
- 限流/熔断判定逻辑无任何差异

## 8. ⚠️ 项目中存在的问题与坑(重要)

### 坑 1:parent 链断裂(家族统一问题)❌
同其他模块,先修 parent 才能编译。详见[家族总览坑 0](../学习总览.md#8-️-全家族注意事项与坑)。

### 坑 2:死文件 + 注释掉的数据源(与 openfeign 同款)⚠️
`flowrule.json` / `degraderule.json` 没有挂载数据源(yml 里注释着,原因同 issue #3033),
实际规则来自代码。**改 JSON 无效。**

### 坑 3:@LoadBalanced 和直连 URL 并存的解释 ⚠️
Bean 上同时有 `@LoadBalanced` 和 `@SentinelRestTemplate`,而调用的是完整域名 URL。
`@LoadBalanced` 本意是把 URL 里的 host 当**服务名**去注册中心解析;
这里 URL 是真实域名、且本模块也没接注册中心,LoadBalancer 找不到该"服务"时会把请求**原样放行直连**
(不同 spring-cloud-loadbalancer 版本行为略有差异,可能打 warning 日志)。
**对本实验无影响**,但要理解:这个注解在这里属于"顺手加上",不是必需品;
生产中直连外部域名时建议去掉,避免歧义。

### 坑 4:默认兜底是 HTTP 429 文案,不是异常 ⚠️
没有自定义 blockHandler 时,被限流/熔断的调用返回 `SentinelClientHttpResponse`(429 + 固定文案),
调用方**不会抛异常**——这和 Feign 的 fallback 一样是"静默降级",注意在业务侧识别,
不要把兜底文案当正常响应处理。

### 坑 5:外网依赖(httpbin.org)⚠️
同 openfeign 模块,先 `curl` 验证网络再排查规则问题。

## 9. 知识点总结与进阶练习

### 本模块覆盖的知识点
- ✅ `@SentinelRestTemplate` 的拦截器机制与资源名拼接规则(`方法:URL到host`)
- ✅ blockHandler 默认行为 vs 自定义(core 模块)对照
- ✅ 同一套规则适配不同客户端(资源抽象的价值)
- ✅ `@LoadBalanced` 与直连 URL 并存时的行为
- ✅ AOT/native 测试的存在意义(顺带了解)

### 推荐动手练习(由浅入深)
1. 修坑 1 → 跑通 7.2 三个实验,并完成 7.3 的双模块对照表
2. 照抄 core 模块的 `ExceptionUtil`,给注解加
   `blockHandler = "handleException", blockHandlerClass = ExceptionUtil.class`,
   把兜底文案改成自定义内容
3. 写一个 `urlCleaner`:把 `https://httpbin.org/get?a=1` 与 `?a=2` 清洗成同一资源
   (资源名默认不带 path,试着扩展成带 path 的精细统计)
4. 离线化:TestController 三个 URL 改指向本地 mock 接口,重配资源名,摆脱外网
5. 进阶:注解上直接配 `degradeGrade`/`degradeCount` 属性,对比与 Manager.loadRules 的优先级
6. 进阶:再建一个不加注解的 RestTemplate Bean(参考 core 模块),双 Bean 对照验证"注解才受保护"

### 一句话总结

> `@SentinelRestTemplate` 一个注解就让老式 RestTemplate 获得限流/熔断能力,
> 规则仍然挂在**资源名**上——与 Feign 模块对照后你会确信:Sentinel 防的是"调用",
> 与你用什么客户端无关。
