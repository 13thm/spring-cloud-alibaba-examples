# Sentinel CircuitBreaker Example — 学习分析文档

> 本文档面向 Spring Cloud Alibaba 初学者。本模块演示 SCA 2023 的新姿势:
> **Feign 的 Sentinel 熔断规则完全用 yml 配置**,一行 Java 规则代码都不用写;
> 而且规则文件放在 **Nacos 配置中心**,可动态调整。
> 它还用一个巧妙技巧——**Feign 调用自己**——做到了单进程演示"服务间熔断"。

## 1. 项目定位:它是什么?

| 维度 | 说明 |
|------|------|
| 演示主题 | Spring Cloud CircuitBreaker 抽象 + Sentinel 实现 + **yml 配置熔断规则** |
| 依赖中间件 | **Nacos 配置中心(必须!)**——熔断规则从 Nacos 拉 |
| 进程模型 | 单进程(Feign 打回自己,无需第二个服务) |
| 与前作的关系 | openfeign 模块是"代码配规则",本模块是"yml 配规则",一脉相承 |

yml 配置规则的三大卖点:
1. **零代码**:不写 `DegradeRuleManager.loadRules`
2. **分级**:全局默认 / 按 Feign 客户端 / 按具体方法,三级覆盖
3. **外置**:规则放 Nacos,改配置即可调熔断策略,不用重新发版

## 3. 核心概念:三种熔断配置姿势的演进

```
姿势一(老):  代码 loadRules()                    → openfeign/resttemplate 模块演示
姿势二(中):  控制台/数据源(file/nacos)              → core 模块演示
姿势三(新):  feign.sentinel.rules 纯 yml 配置      → 本模块!
```

姿势三的开关有两个,缺一不可:

```yaml
feign:
  circuitbreaker:          # Spring Cloud OpenFeign 的总开关:
    enabled: true          #   Feign 调用经由 Spring Cloud CircuitBreaker 抽象包装(才能挂降级)
  sentinel:                # SCA 扩展配置:
    default-rule: default  #   没有专属规则的客户端,统一用 "default" 键下的规则
    rules: { ... }         #   规则本体(三级键,见第 6 节)
```

> 💡 理解 `feign.circuitbreaker.enabled` 的含义:它是 OpenFeign 官方开关,打开后 Feign 的每个方法
> 都会被 CircuitBreaker(此处实现为 Sentinel)包一层;`fallback` 属性的降级也必须开着它才生效。
> 而 `feign.sentinel.*` 是 SCA 对"规则从哪来"的扩展。

## 4. 巧妙设计:Feign 自调用

正常熔断演示需要两个服务(A 调 B,B 报错)。本模块的做法:

```java
@FeignClient(value = "order",
             url = "http://localhost:${server.port}",      // ← URL 指向自己!
             fallback = OrderClientFallBack.class)
public interface OrderClient {
    @GetMapping("/default/{ok}")
    String defaultConfig(@PathVariable boolean ok);
}
```

- `url = "http://localhost:${server.port}"`:**绕过注册中心直接打回本进程**(端口 80)
- ApiController 提供同名接口:`ok=true` 返回 "ok",`ok=false` 抛 RuntimeException
- 于是单进程内完成了"上游→Feign→下游异常→降级→熔断→恢复"的完整闭环

```
TestController(上游) ──Feign──► ApiController(下游,自己)
      │                            ok=false → 抛异常
      ▼
OrderClientFallBack / UserClientFallBack 降级
```

## 5. 代码逐文件精读

### 5.1 ApiController — 扮演"不靠谱的下游"

```java
@RestController
public class ApiController {

	@GetMapping("/default/{ok}")
	public String defaultConfig(@PathVariable boolean ok) {
		if (ok) return "ok";
		throw new RuntimeException("fail");       // 故意失败,制造异常样本
	}
	// /feign/{ok}、/feignMethod/{ok} 同款逻辑
}
```

### 5.2 TestController — 3 个实验入口(对应三级规则)

```java
@RestController
public class TestController {

	@GetMapping("/test/default/{ok}")      // → OrderClient, 命中【default 全局规则】
	public String testDefault(@PathVariable boolean ok) { return orderClient.defaultConfig(ok); }

	@GetMapping("/test/feign/{ok}")        // → UserClient.feign, 命中【user 客户端规则】
	public String testFeign(@PathVariable boolean ok) { return userClient.feign(ok); }

	@GetMapping("/test/feignMethod/{ok}")  // → UserClient.feignMethod, 命中【方法级规则】
	public String testFeignMethod(@PathVariable boolean ok) { return userClient.feignMethod(ok); }
}
```

### 5.3 降级类 — 最简单的 fallback(对比 openfeign 的 factory)

```java
@Component
public class OrderClientFallBack implements OrderClient {
	@Override
	public String defaultConfig(boolean ok) { return "order fallback"; }
}
```

本模块用的是**普通 fallback**(不需要拿异常原因),注册成 `@Component` 即可。
与 openfeign 模块的 fallbackFactory 是两种姿势的完整对照。

## 6. 规则文件精读:三级优先级

📄 `sentinel-circuitbreaker-rules.yml`(本地模板,**生效的前提是把它导入 Nacos**,见坑 2):

```yaml
feign:
  circuitbreaker:
    enabled: true
  sentinel:
    default-rule: default
    rules:
      # ① 全局默认:所有没被单独配置的 Feign 客户端
      default:
        - grade: 2            # 2 = 异常数策略
          count: 1            # 1 次异常
          minRequestAmount: 1 # 最小请求数 1
          statIntervalMs: 1000
          timeWindow: 15      # 熔断 15 秒
      # ② 客户端级:只对 value="user" 的 FeignClient 生效
      user:
        - { grade: 2, count: 1, timeWindow: 15, statIntervalMs: 1000, minRequestAmount: 1 }
      # ③ 方法级:只对 user 客户端的 feignMethod(boolean) 方法生效(格式: "客户端名#方法(参数类型)")
      "[user#feignMethod(boolean)]":
        - { grade: 2, count: 1, timeWindow: 10, statIntervalMs: 1000, minRequestAmount: 1 }
```

**优先级:方法级(③) > 客户端级(②) > 全局默认(①)**

| 实验入口 | 命中的规则 | 熔断时长 |
|----------|-----------|----------|
| `/test/default/false` | `default` | 15 秒 |
| `/test/feign/false` | `user`(客户端级) | 15 秒 |
| `/test/feignMethod/false` | `[user#feignMethod(boolean)]` | **10 秒** |

三个 timeWindow 不同(15/15/10),正是为了让你**用恢复时间反推命中的是哪级规则**。

## 7. 一次熔断的完整流程图

```
浏览器 → GET /test/default/false
      │
      ▼
TestController → orderClient.defaultConfig(false)  (Feign 动态代理)
      │
      ▼
CircuitBreaker 包裹(feign.circuitbreaker.enabled=true)
  资源: order#defaultConfig(boolean)
      │
      ▼
Sentinel 查规则: 无方法级/客户端级(order 没有) → 用 default 规则
  熔断器状态? ──关闭──► 放行,Feign HTTP → 本机 /default/false
      │                      │ ApiController 抛 RuntimeException → HTTP 500
      │                      ▼
      │              异常计数 1 ≥ count(1) 且已达 minRequestAmount(1)
      │                      │
      │                      ▼
      │              熔断器【打开】15 秒 + 本次走 fallback
      ▼
返回 "order fallback" ❌

15 秒内的任何请求(即使传 true):
  熔断器打开 → 直接 fallback(不再发 HTTP)
15 秒后 → 半开,放一个请求试探:
  true → 关闭熔断器,恢复正常
  false → 继续熔断 15 秒
```

## 8. 如何运行与实验设计

### 8.1 前置(本模块对 Nacos 是硬依赖!)

1. 启动 **Nacos**(8848,账号 nacos/nacos)
2. 在 Nacos 控制台新建配置:
   - **Data ID**: `sentinel-circuitbreaker-rules.yml`
   - **Group**: `DEFAULT_GROUP`(默认)
   - **格式**: YAML
   - **内容**: 抄模块里的 `src/main/resources/sentinel-circuitbreaker-rules.yml`(去掉 license 注释头)
3. 确认本机 **80 端口**空闲(circuitbreaker 模块用 80)
4. 修坑 1 后启动:`mvn spring-boot:run`

### 8.2 实验清单(注意每步间隔与秒表)

```bash
# 实验 1:全局默认规则(timeWindow=15s)
curl http://localhost:80/test/default/false
# → "order fallback"(真异常触发降级)
curl http://localhost:80/test/default/true
# → "order fallback"!★ 熔断已打开,即使传 true 也降级
# 等 15 秒后:
curl http://localhost:80/test/default/true
# → "ok" 半开试探成功,熔断器关闭

# 实验 2:客户端级规则(user,timeWindow=15s)
curl http://localhost:80/test/feign/false     # → user fallback,熔断打开
curl http://localhost:80/test/feign/true      # → user fallback(熔断中)

# 实验 3:方法级规则(timeWindow=10s,恢复更快!)
curl http://localhost:80/test/feignMethod/false   # → user fallback,熔断打开
curl http://localhost:80/test/feignMethod/true    # → user fallback
# 只需等 10 秒即恢复 —— 证明命中的是方法级规则而非 15 秒的客户端级

# 实验 4(进阶):在 Nacos 上把 default 的 timeWindow 改成 5,
# 重新触发熔断,观察恢复时间变化(部分场景需重启应用,规则绑定时机见坑 3)
```

### 8.3 观察要点
- 熔断打开期间**传 true 也返回 fallback**——这是熔断区别于"每次都失败"的铁证
- 用三个接口的**恢复时长差异**(15/15/10 秒)验证三级规则匹配
- 本模块没接 Sentinel 控制台配置,可在 Nacos 控制台观察配置变更历史

## 9. ⚠️ 项目中存在的问题与坑(重要)

### 坑 1:parent 链断裂(家族统一问题)❌
同其他模块,先修 parent 才能编译。详见[家族总览坑 0](../学习总览.md#8-️-全家族注意事项与坑)。

### 坑 2:本地规则文件不会被自动读取!⚠️⚠️
最最容易踩的坑:`src/main/resources/sentinel-circuitbreaker-rules.yml` 只是**参考模板**。
`application.yml` 里 `spring.config.import: optional:nacos:sentinel-circuitbreaker-rules.yml`
导入的是 **Nacos 上的同名配置**。没在 Nacos 建配置时:
- `optional:` 前缀让导入失败被静默忽略,应用照常启动
- 但 `feign.sentinel.rules` 不存在 → **熔断规则全空**
- 现象:fallback 只在"真失败"时触发,永远不会"熔断"(true 也降级的现象消失)
**排查口诀:先查 Nacos 里有没有这个 Data ID。**

### 坑 3:规则的动态性有限 ⚠️
`feign.sentinel.rules` 在应用启动时绑定(配置属性方式)。Nacos 上改配置,
**是否即时生效取决于 SCA 版本的属性刷新机制**——最可靠的验证方法是改完配置后重启应用对比。
(别把它当成 core 模块 Nacos 数据源那种"推即生效"。)

### 坑 4:80 端口 ⚠️
- Windows 上 80 常被 IIS/其他前端工具占用;公司内网机器还可能没权限
- 与 Sentinel 控制台的 8080 不冲突,但**千万别改 yml 时只改 server.port 忘了 Feign 的
  `url = "http://localhost:${server.port}"` 是占位符**——它俩是联动的(这也是占位符的好处)

### 坑 5:方法级规则的键格式极易写错 ⚠️
```yaml
"[user#feignMethod(boolean)]":
```
- 必须整体加**引号**(键里有 `#` 和 `()`,不加引号 YAML 解析错乱)
- `方法名(参数类型列表)`:参数类型要写**简单类名**(boolean、int、String),
  与接口签名完全一致,多个参数逗号分隔、不留空格
- 写错的典型症状:方法级规则不命中,退回客户端级规则(恢复时间从 10 秒变 15 秒)

### 坑 6:fallback 不会拦截非熔断类异常? ⚠️
注意 fallback 生效范围:Feign 调用产生的异常(含熔断打开)都会走 fallback;
但若 fallback Bean 本身没注册成 `@Component`(本项目已注册),或
`feign.circuitbreaker.enabled` 没开,降级整体失效、异常直接抛给浏览器(500)。

## 10. 知识点总结与进阶练习

### 本模块覆盖的知识点
- ✅ Spring Cloud CircuitBreaker 抽象:`feign.circuitbreaker.enabled` + Sentinel 实现
- ✅ SCA 新特性:`feign.sentinel.default-rule` / `feign.sentinel.rules` 纯 yml 配规则
- ✅ 规则三级优先级:方法级 > 客户端级 > 全局默认
- ✅ Feign 自调用技巧(`url` 指向 `${server.port}`)单进程模拟两个服务
- ✅ 普通 fallback 与 fallbackFactory 两种降级姿势的适用场景
- ✅ `spring.config.import: optional:nacos:` 引入远程配置的语法
- ✅ 熔断器完整生命周期:关闭 → 打开 → 半开 → 恢复

### 推荐动手练习(由浅入深)
1. 修坑 1、按 8.1 把规则导入 Nacos → 跑通 8.2 全部实验,用秒表记录三档恢复时间
2. 故意删掉 Nacos 里的 `user` 键配置,验证 `/test/feign` 退回 default 规则(恢复时间 15 秒)
3. 把方法级规则的键改成 `"[user#feign(boolean)]"`(张冠李戴),观察 feignMethod 退回 15 秒,
   体会键匹配的严格性
4. 给 UserClientFallback 打印堆栈(openfeign 模块同款),观察熔断时抛的是 `DegradeException`
5. 把 grade 改成 0(慢调用)、count 改成 100,在 ApiController 对应方法里加 `Thread.sleep(200)`,
   做慢调用版实验
6. 进阶:把本模块改造成"真双进程":复制一份服务改端口,OrderClient 的 url 指向另一个进程,
   验证熔断逻辑完全不变
7. 进阶:对比 core 模块的 Nacos 数据源方式(ds6)与本模块的 config.import 方式,
   总结"规则外置"的两种实现思路差异

### 一句话总结

> 熔断的三种配置姿势里,本模块演示的是**最工程化**的一种:规则全在 yml(放 Nacos),
> 三级键精准覆盖"全局/客户端/方法",配合自调用技巧一个进程讲完整个故事——
> 代价是要先迈过"必须在 Nacos 建配置"这道最容易忽视的坎。
