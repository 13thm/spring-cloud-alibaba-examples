# Sentinel OpenFeign Example — 学习分析文档

> 本文档面向 Spring Cloud Alibaba 初学者。本模块演示 **OpenFeign 声明式调用 + Sentinel 熔断限流**:
> Feign 接口像调本地方法一样调远程服务,Sentinel 在背后对每次远程调用做统计与拦截,
> 被限流/熔断时走 **fallbackFactory 降级**(还能拿到失败原因)。
> 规则采用**代码方式加载**(`FlowRuleManager.loadRules`),并演示了 file 数据源的已知坑。

## 1. 项目定位:它是什么?

调用方视角的 Sentinel 教学模块:**我是消费者,下游不靠谱(慢/报错),我如何自保?**

| 教学点 | 实现 |
|--------|------|
| Feign 接入 Sentinel | `feign.sentinel.enabled: true` |
| 降级时拿到失败原因 | `fallbackFactory`(而不是 fallback) |
| QPS 限流(正常接口) | `/get` 规则:QPS=1 |
| 异常数熔断(下游报错) | `/status/500` 规则:1 次异常熔断 30s |
| 慢调用熔断(下游超时) | `/delay/3` 规则:RT>1ms 且慢比例 10% 熔断 30s |
| 代码方式加载规则 | `@PostConstruct` + Manager.loadRules |

被调方是公共测试站 **httpbin.org**(返回 JSON/500/延迟),因此**不需要再启动任何服务**。

## 3. 核心概念:Feign 资源名与降级三件套

### 3.1 feign.sentinel.enabled 做了什么?
开启后,Sentinel 会替换 Feign 的 Builder(FeignCircuitBreaker → SentinelFeignCircuitBreaker),
为**每个 `@FeignClient` 方法**自动生成调用链:发请求前进入 Sentinel 资源,
失败/被拦时执行降级。**Feign 的资源名格式:`方法:协议://host/路径`**,
例如本模块的 `GET:https://httpbin.org/get`(规则里的 resource 必须一字不差)。

### 3.2 fallback vs fallbackFactory(重要区别!)

| 方式 | 拿得到失败原因? | 写法 |
|------|:---------------:|------|
| `fallback = Xxx.class` | ❌ | 普通类实现 Feign 接口 |
| `fallbackFactory = Xxx.class` | ✅ | 实现 `FallbackFactory<T>`,create(Throwable) 时把异常传给你 |

生产建议用 **fallbackFactory**——降级时能记录是因为限流、熔断、超时还是 404,
否则排查"为什么总走降级"全靠猜。本模块演示的就是 factory 方式。

## 4. HttpbinClient + 降级类分析

📄 `HttpbinClient.java`:

```java
@FeignClient(name = "openfeign-example",                 // 名字随便起(url 直连时不用去注册中心找)
             url = "https://httpbin.org",                // 直连目标,不走服务发现
             contextId = "openfeign-example",
             fallbackFactory = EchoServiceFallbackFactory.class)
public interface HttpbinClient {

	@GetMapping("/delay/3")     String delay();          // 3 秒后才返回 → 演示慢调用
	@GetMapping("/status/500")  String status500();      // 固定返回 500 → 演示异常
	@GetMapping("/get")         String get();            // 正常返回 JSON → 演示限流
}
```

📄 `EchoServiceFallbackFactory.java`(降级工厂):

```java
@Component
public class EchoServiceFallbackFactory implements FallbackFactory<HttpbinClientFallback> {
	@Override
	public HttpbinClientFallback create(Throwable throwable) {
		return new HttpbinClientFallback(throwable);   // 每次失败 new 一个,携带异常
	}
}
```

📄 `HttpbinClientFallback.java`(降级实现):

```java
public class HttpbinClientFallback implements HttpbinClient {
	private Throwable throwable;                        // 保存失败原因

	HttpbinClientFallback(Throwable throwable) { this.throwable = throwable; }

	@Override public String delay()    { return "delay degrade by sentinel"; }
	@Override public String status500(){ return "500 degrade by sentinel"; }
	@Override public String get()      { return "get degrade by sentinel"; }
}
```

**协作链**:`调用失败/被拦` → Sentinel 调 `factory.create(异常)` → 返回降级实例 →
执行同名方法返回兜底文案。三个接口各返回不同文案,便于区分是哪条规则触发的。

> 💡 注意 `HttpbinClientFallback` **故意不注册为 Bean**,由工厂动态创建——
> 这是 factory 模式的标准写法(Bean 是"单例无状态",降级实例需要每次携带异常)。

## 5. 规则加载:SentinelRulesConfiguration 逐行精读

📄 `SentinelRulesConfiguration.java`(精简后):

```java
@Component
public class SentinelRulesConfiguration {

	@PostConstruct                                    // Bean 初始化完成后执行
	public void init() {
		// ── 流控规则:GET https://httpbin.org/get, QPS=1 ──
		FlowRule flowRule = new FlowRule();
		flowRule.setResource("GET:https://httpbin.org/get");   // ★ 与 Feign 资源名严格一致
		flowRule.setCount(1);                                   // QPS 阈值 1
		flowRule.setGrade(RuleConstant.FLOW_GRADE_QPS);         // 按 QPS
		flowRule.setControlBehavior(RuleConstant.CONTROL_BEHAVIOR_DEFAULT);  // 快速失败
		flowRule.setStrategy(RuleConstant.STRATEGY_DIRECT);
		flowRule.setLimitApp("default");
		FlowRuleManager.loadRules(List.of(flowRule));           // 装进流控管理器

		// ── 熔断规则 1:异常数策略 ──
		DegradeRule r1 = new DegradeRule();
		r1.setResource("GET:https://httpbin.org/status/500");
		r1.setGrade(RuleConstant.DEGRADE_GRADE_EXCEPTION_COUNT); // 2=异常数
		r1.setCount(1);                 // 1 次异常
		r1.setMinRequestAmount(1);      // 最小请求数 1(默认是 5,这里改 1 方便演示)
		r1.setTimeWindow(30);           // 熔断 30 秒
		DegradeRuleManager.loadRules(List.of(r1, r2));

		// ── 熔断规则 2:慢调用比例策略 ──
		DegradeRule r2 = new DegradeRule();
		r2.setResource("GET:https://httpbin.org/delay/3");
		r2.setGrade(RuleConstant.DEGRADE_GRADE_RT);   // 0=慢调用比例
		r2.setCount(1);                    // RT 阈值 1ms(比 1ms 慢就算慢调用)
		r2.setSlowRatioThreshold(0.1);     // 慢调用占比 > 10% 触发
		r2.setMinRequestAmount(1);
		r2.setTimeWindow(30);
	}
}
```

**三条规则的效果翻译:**

| 规则 | 通俗描述 |
|------|----------|
| get 限流 | 每秒只允许 1 次对 `/get` 的调用,第 2 次直接降级 `get degrade by sentinel` |
| status500 熔断 | 1 次异常即熔断 30 秒——熔断打开期间**根本不发请求**,直接返回 `500 degrade by sentinel` |
| delay3 熔断 | 请求超过 1ms 就算慢(故意设得极低),慢比例超 10% → 熔断 30 秒,期间秒回 `delay degrade by sentinel` |

> 💡 这是**代码配置规则**的标准范式:Manager.loadRules()。优点直观、无依赖;
> 缺点是改规则要重新发布。core 模块演示了文件/Nacos 数据源,circuitbreaker 模块演示了 yml 配置,
> 三种方式对照着记。

## 6. 配置文件分析 application.yml

```yaml
server:
  port: 18087

spring:
  application:
    name: sentinel-openfeign-example
  cloud:
    sentinel:
      transport:
        dashboard: localhost:8080     # 控制台
      eager: true
#      datasource:                    # ⚠️ 整段被注释——file 数据源在 jar 模式有坑,见坑 2
#        ds1.file: { file: "classpath: degraderule.json", ruleType: degrade, dataType: json }
#        ds2.file: { file: "classpath: flowrule.json", ruleType: flow, dataType: json }

feign:
  sentinel:
    enabled: true                     # ★ Sentinel 接管 Feign 的总开关
```

关键就一个:`feign.sentinel.enabled: true`。不开的话,fallbackFactory 完全不生效
(Feign 会直接把异常抛给你)。

## 7. 一次熔断请求的完整流程图

以"第一次调用 `GET /exp`(对应 httpbin /status/500)"为例:

```
浏览器 → GET http://localhost:18087/exp
      │
      ▼
TestController.exp() → httpbinClient.status500()   (Feign 动态代理)
      │
      ▼
Sentinel 接管(feign.sentinel.enabled=true)
  资源名: GET:https://httpbin.org/status/500
      │
      ├─ DegradeSlot 检查熔断器: 关闭 → 放行,真正发 HTTP 请求
      │        │
      │        ▼
      │   httpbin 返回 500 → Feign 抛 FeignException → 记 1 次异常
      │        │ (异常数策略: 1 次已达阈值 → 打开熔断器 30 秒)
      │        ▼
      │   本次调用失败 → EchoServiceFallbackFactory.create(FeignException)
      │        │
      │        ▼
      │   "500 degrade by sentinel"          ← 第一次: 异常导致的降级
      ▼
浏览器拿到降级文案

30 秒内的后续请求(即使 httpbin 恢复正常):
      DegradeSlot: 熔断器打开 → 不发请求,直接降级   ← 这就是"熔断"
      30 秒后 → 半开,放一个试探请求 → 成功则关闭熔断器
```

## 8. 如何运行与实验设计

### 8.1 前置
1. (推荐)Sentinel 控制台 8080
2. **外网可达 httpbin.org**(验证:`curl https://httpbin.org/get`)
3. 修坑 1 后启动,端口 **18087**

### 8.2 实验清单(重点体会"限流"与"熔断"的差异)

```bash
# 实验 1:QPS 限流。1 秒内刷 2 次,第 2 次被拦
curl http://localhost:18087/get
curl http://localhost:18087/get      # → get degrade by sentinel(限流降级,请求没发出去)

# 实验 2:异常数熔断
curl http://localhost:18087/exp      # → 真请求 → httpbin 500 → 500 degrade by sentinel
curl http://localhost:18087/exp      # → 熔断已打开 → 秒回 500 degrade by sentinel
# 继续刷,30 秒内全部秒回;30 秒后半开试探

# 实验 3:慢调用熔断(耐心等 3 秒)
curl http://localhost:18087/rt       # → 第一次:等 ~3 秒才返回(真调用),返回降级文案
curl http://localhost:18087/rt       # → 熔断打开 → 秒回 delay degrade by sentinel
```

### 8.3 观察降级原因(fallbackFactory 的价值)
把 `HttpbinClientFallback` 的方法里加一行 `throwable.printStackTrace()`,
就能在控制台看到是 `DegradeException`(熔断)、`FlowException`(限流)还是 `FeignException`(真失败)——
这是 factory 相比普通 fallback 最大的实用价值。

## 9. ⚠️ 项目中存在的问题与坑(重要)

### 坑 1:parent 链断裂(家族统一问题)❌
同其他模块,先修 parent 才能编译。详见[家族总览坑 0](../学习总览.md#8-️-全家族注意事项与坑)。

### 坑 2:flowrule.json / degraderule.json 是"死文件" ⚠️
resources 里有两份规则 JSON,但 yml 的 file 数据源**整段被注释**,
实际生效的是 `SentinelRulesConfiguration` 里代码加载的规则。
注释原因见官方 issue(alibaba/spring-cloud-alibaba#3033):classpath 文件数据源在打 jar 运行时读取有问题。
**别误以为改 JSON 就能改规则**——想用文件数据源,放开注释并用 `mvn spring-boot:run` 跑。

### 坑 3:degraderule.json 与代码规则"长得不一样" ⚠️
JSON 里 `/delay/3` 是 `"grade": 0`(慢调用),`/status/500` 是 `"grade": 2`(异常数)——
与代码常量一致,但字段名有新旧差异(`minRequestAmount` vs 老教程的 `passCount`),
抄老博客注意版本(本仓库 Sentinel 1.8.x 语义)。

### 坑 4:外网依赖导致"假性不生效" ⚠️
httpbin.org 慢/被墙时:`/rt` 长时间无响应、`/exp` 超时异常,容易误判规则失效。
先 `curl` 验证网络,再查规则。彻底解法见进阶练习 4(换成本地 mock)。

### 坑 5:name 与 url 直连的语义 ⚠️
`@FeignClient(name="openfeign-example", url="https://httpbin.org")`:一旦写了 url,
Feign 就**直连该地址**,name 不再用于服务发现(但仍是资源名/上下文的组成部分)。
初学者常见疑问:"openfeign-example 这个服务在哪?"——它不存在,也不需要存在。

## 10. 知识点总结与进阶练习

### 本模块覆盖的知识点
- ✅ `feign.sentinel.enabled` 接管 Feign 的机制与 Feign 资源名(`GET:https://host/path`)
- ✅ fallbackFactory 降级三件套:接口 + 工厂 + 实现,降级可拿到 Throwable
- ✅ 代码加载规则范式:`FlowRuleManager` / `DegradeRuleManager` + `@PostConstruct`
- ✅ QPS 限流 / 异常数熔断 / 慢调用比例熔断 三种策略对照实验
- ✅ `minRequestAmount` 调成 1 方便教学(默认 5,生产慎改,防偶发误杀)
- ✅ 熔断器生命周期:关闭 → 打开(快速失败)→ 半开试探 → 恢复

### 推荐动手练习(由浅入深)
1. 修坑 1 → 跑通 8.2 三个实验,用秒表/时间戳记录"熔断打开/恢复"的时间线
2. 在降级类里打印 Throwable,区分 FlowException / DegradeException / FeignException
3. 把 `/get` 的 QPS 改成 3(控制台改,或改代码重启),验证限流阈值变化
4. 离线化:写一个本地 Controller(`/mock/500`、`/mock/delay`),把 HttpbinClient 的 url
   指向 `http://localhost:18087`,摆脱外网依赖
5. 对照 resttemplate 模块:同样三个实验用 RestTemplate 再做一遍,体会两种客户端资源名的异同
6. 进阶:`minRequestAmount` 改回 5,连续刷 5 次 `/exp` 才熔断,验证"最小请求数"的防抖作用
7. 进阶:去掉 fallbackFactory,观察异常直接抛给调用方(500)的样子,理解"没有降级时熔断毫无意义"

### 一句话总结

> Feign + Sentinel 的组合拳:**声明式调用零样板,一条开关接哨兵,规则配到资源名上,
> 出事兜底 fallbackFactory**——这是消费者自我保护的标准姿势,
> 也是 circuitbreaker 模块(纯 yml 新姿势)的前置知识。
