# Sentinel Example 全家族学习总览 — 微服务流量防卫兵

> Sentinel 是 Spring Cloud Alibaba 三大件(Nacos / Sentinel / Seata)中的"**稳定性防线**":
> Nacos 管注册与配置,Seata 管分布式事务,而 Sentinel 管**流量**——限流、熔断降级、热点防护、系统保护。
> 本家族共 6 个模块,覆盖了 Sentinel 在 Web MVC、WebFlux、OpenFeign、RestTemplate、
> Spring Cloud Gateway 五种技术栈下的接入姿势。本篇是总纲,6 个模块各有独立精读文档。

## 1. 一句话理解 Sentinel

> 微服务里,一个接口被刷爆、一个下游服务拖慢整条链路、一个大促流量把系统压垮——
> Sentinel 的思路是:**在每个服务的入口和出口埋"哨兵",按预设规则对流量放行 / 排队 / 拒绝 / 降级**,
> 让系统"过载时宁可拒绝一部分请求,也不整体雪崩"。

三个最典型的能力(本家族全部演示):

| 能力 | 通俗解释 | 演示模块 |
|------|----------|----------|
| **流量控制 (FlowControl)** | `/hello` 每秒只放行 1 个请求,超了直接拒绝 | core / webflux / openfeign / resttemplate / gateway |
| **熔断降级 (CircuitBreaking)** | 下游接口 1 秒内异常 1 次 → 熔断 30 秒,期间不再真正调用,直接走兜底逻辑 | circuitbreaker / openfeign / webflux / core |
| **热点参数限流 (ParamFlow)** | `b=2` 这个参数值每秒只放 1 次,其他参数不限 | core / gateway |

> 💡 与 Hystrix 的关系(面试常问):Hystrix 已停更,主打熔断、线程池隔离;
> Sentinel 功能更全(限流+熔断+热点+系统自适应),基于**滑动窗口统计 + 信号量隔离**,
> 且有控制台、规则可动态推送,是当前国内主流选择。

## 2. 核心概念速览(必读)

读任何 Sentinel 代码前,先建立这 5 个概念:

```
┌────────────────────────────────────────────────────────────────┐
│ ① 资源 Resource —— "保护谁"                                     │
│    一个 URL、一个方法、一个 Feign 调用、一个网关路由,都可以是资源   │
│    接入方式:CommonFilter 自动埋点 / @SentinelResource 注解 /     │
│             @SentinelRestTemplate / SentinelReactorTransformer  │
│                                                                │
│ ② 规则 Rule —— "怎么保护"                                       │
│    流控规则 / 熔断规则 / 热点规则 / 系统规则 / 授权规则 / 网关规则  │
│                                                                │
│ ③ 数据源 DataSource —— "规则从哪来"                              │
│    代码写死(Manager.loadRules)/ 文件 / Nacos / ZooKeeper / Apollo│
│    ——生产推荐 Nacos 等配置中心,规则可动态推送、可持久化           │
│                                                                │
│ ④ Slot 处理链 —— "规则怎么生效"                                  │
│    每次访问资源都会过一遍责任链:                                  │
│    NodeSelectorSlot → ClusterBuilderSlot → StatisticSlot(统计)   │
│    → AuthoritySlot → SystemSlot → ParamFlowSlot → FlowSlot       │
│    → DegradeSlot(熔断) → 入口业务代码                            │
│    (统计在前、判断在后,这就是 Sentinel 的"插槽"架构)             │
│                                                                │
│ ⑤ 控制台 Dashboard —— "人怎么看"                                 │
│    独立 jar(默认 8080 端口),应用把心跳和监控数据上报给它,         │
│    也能在页面上改规则(默认存内存,重启即丢,见坑 5)                │
└────────────────────────────────────────────────────────────────┘
```

一次请求被限流的完整过程:

```
请求 → 埋点(SentinelResource/Filter) → 进入 Slot 链
     → StatisticSlot 滑动窗口计数(默认 1s 窗口 / 500ms 桶)
     → FlowSlot 查规则: QPS 超阈值? ──是──► 抛 BlockException
     → DegradeSlot 查熔断器: 打开?   ──是──► 抛 DegradeException
     → 全部通过 ──► 真正执行业务
被拦截的请求去哪? → blockHandler 兜底 / block-page 错误页 / fallback 降级 / 网关 444
```

## 3. 五大规则 + 网关规则速查表

> ⚠️ 注意:Sentinel **1.8 之后熔断策略编号有变化**,网上老教程常把 0/1/2 写反,以下为 1.8+ 语义。

### 3.1 流控规则 FlowRule(rule-type: `flow`)

```json
{ "resource": "/hello", "grade": 1, "count": 1,
  "limitApp": "default", "strategy": 0, "controlBehavior": 0 }
```

| 字段 | 取值 | 含义 |
|------|------|------|
| `grade` | 0 / **1** | 0=按并发线程数,**1=按 QPS**(常用) |
| `count` | 任意数 | 阈值。**QPS 阈值 0 = 全部拒绝**(不是"不限流"!坑 4) |
| `strategy` | 0/1/2 | 0=直接限流,1=关联(关联资源达到阈值时限自己),2=链路(只限某入口来源) |
| `controlBehavior` | 0/1/2 | 0=快速失败,**1=Warm Up(冷启动预热)**,2=排队等待(匀速漏桶) |
| `limitApp` | `default`/服务名 | 针对哪个调用方限流 |

### 3.2 熔断规则 DegradeRule(rule-type: `degrade`)

```json
{ "resource": "aa", "grade": 0, "count": 20.0, "timeWindow": 10,
  "minRequestAmount": 5, "statIntervalMs": 1000 }
```

| 字段 | 含义 |
|------|------|
| `grade` | **0=慢调用比例**(count=RT 阈值 ms,另配 `slowRatioThreshold` 慢调用占比)、**1=异常比例**(count=0~1)、**2=异常数**(count=整数次) |
| `count` | 阈值(随 grade 语义变化,上表) |
| `timeWindow` | 熔断时长(秒),熔断期结束后进入**半开**,放一个请求试探 |
| `minRequestAmount` | 统计窗口内**至少这么多请求**才触发熔断(默认 5,防偶发误杀) |
| `statIntervalMs` | 统计窗口时长(默认 1000ms) |

### 3.3 热点规则 ParamFlowRule(rule-type: `param_flow`)

对**参数值**精细化限流:比如"订单 ID=12345 这个热点参数单独限 1 QPS"。
`paramIdx` 指定第几个参数,`paramFlowItemList` 列出"特例参数值 → 独立阈值"。

### 3.4 系统规则 SystemRule(rule-type: `system`)

从**整个应用**维度保护:`qps`(入口总 QPS)、`avgRt`(平均 RT)、`maxThread`(并发线程数)、
`highestSystemLoad`(Load,需开 CPU 监控)、`highestCpuUsage`。-1 表示该项不启用。

### 3.5 授权规则 AuthorityRule(rule-type: `authority`)

黑白名单:`strategy` 0=白名单(只允许 `limitApp` 列的来源),1=黑名单。
来源由调用方通过 `RequestOriginParser` 解析(如取某个请求头)。

### 3.6 网关规则(rule-type: `gw-flow` / `gw-api-group`)

Gateway 专用:`gw-flow` 是网关流控规则(支持按 Route ID 或 API 分组、按请求头/URL 参数/Client IP 热点限流);
`gw-api-group` 把任意多条路径打包成一个"API 分组"再按组限流。详见 gateway 模块文档。

## 4. 资源命名规则汇总(跨模块对照,重要!)

> 配规则 90% 的错误都是**资源名对不上**:规则写了 A,实际资源叫 B,规则永远不生效。
> 不同接入方式,资源名的"长相"完全不同:

| 接入方式 | 资源名样子 | 示例 | 所在模块 |
|----------|-----------|------|----------|
| Web MVC CommonFilter(自动) | `URL路径` | `/hello` | core |
| WebFlux Filter(自动) | `URL路径` | `/mono` | webflux |
| `@SentinelResource("xxx")` | `注解里的名字` | `resource`、`aa` | core |
| `@SentinelRestTemplate` | `方法:完整URL` | `GET:http://www.taobao.com` | core / resttemplate |
| Feign(feign.sentinel.enabled=true) | `方法:协议://host/路径` | `GET:https://httpbin.org/get` | openfeign |
| 新版 yml 熔断规则键 | `客户端名#方法(参数)` | `[user#feignMethod(boolean)]` | circuitbreaker |
| Spring Cloud Gateway | `Route ID` 或 `API分组名` | `httpbin_route`、`some_customized_api` | gateway |
| CircuitBreakerFactory | `create(id) 的 id` | `slow`、`slow_mono` | core / webflux |

> 💡 去 Sentinel 控制台"实时监控/簇点链路"页面,能看到每个资源**真实的名字**,
> 拿它去配规则,永远错不了——这是排查"规则不生效"的第一招。

## 6. 环境搭建与运行

### 6.1 Sentinel 控制台(强烈建议,学习神器)

```bash
# 下载: https://github.com/alibaba/Sentinel/releases → sentinel-dashboard-1.8.x.jar
java -jar sentinel-dashboard-1.8.8.jar          # 默认端口 8080,账号/密码 sentinel/sentinel
```

各模块 yml 里都已配 `spring.cloud.sentinel.transport.dashboard: localhost:8080` + `eager: true`
(启动即注册,不用等第一次请求)。控制台没起应用也能跑,只是看不到监控。

### 6.2 Nacos(仅 circuitbreaker 必须,core 的 ds6 可选)

```bash
sh startup.sh -m standalone    # 127.0.0.1:8848,账号 nacos/nacos
```

- **circuitbreaker 模块**:必须在 Nacos 建 `dataId = sentinel-circuitbreaker-rules.yml`
  (内容抄模块里的同名文件),否则熔断规则不生效,详见该模块文档。
- **core 模块**:ds6 数据源指向 Nacos 的 `flowrule.json`,没启 Nacos 会刷连接错误日志。

### 6.3 外网可达性

openfeign / resttemplate / webflux / gateway 都调用公共测试站 **httpbin.org**
(`/get`、`/status/500`、`/delay/3` 分别演示正常 / 异常 / 慢调用)。国内访问偶尔慢或被墙,
现象是请求超时——**这不是 Sentinel 的问题**;可以把 URL 换成本地 mock 服务再实验。

### 6.4 编译前置:先修坑 0

当前根 pom 已是 `com.thm.cloud` 空壳,sentinel 6 个模块的 parent 仍指向
`com.alibaba.cloud:${revision}` → 直接 `mvn` 会报 parent 找不到。修法见[坑 0](#8-️-全家族注意事项与坑)。

## 7. 企业里怎么用?

### 7.1 真实场景
- **网关层限流**:大促/秒杀总闸门(gateway 模块姿势),按 API 分组 + 用户维度参数限流
- **核心接口保护**:下单、支付接口按 QPS 限流,超量快速失败 + 友好提示
- **依赖熔断**:下游服务抖动(RT 飙高 / 报错率高)时熔断,走兜底逻辑,防止雪崩
- **热点商品**:秒杀商品 ID 单独限流(param-flow),避免热点 key 打爆缓存与 DB

### 7.2 部署形态
- 应用引入 `spring-cloud-starter-alibaba-sentinel`,控制台独立部署
- **规则必须持久化**:控制台默认改规则只存应用内存,应用重启即丢。
  生产标配是"控制台 → Nacos → 应用"推拉结合,即规则存 Nacos(本家族 core/openfeign 已演示文件/Nacos 数据源形态)
- 网关层 + 服务层双层防线:网关挡总量,服务层保自己

### 7.3 与同类产品对比口径
```
Hystrix(停更):线程池隔离为主,开销大,无控制台
Resilience4j:轻量、与 Spring Cloud CircuitBreaker 抽象集成好,无控制台/无限流
Sentinel:功能最全(限流/熔断/热点/系统/控制台),阿里系生态默认
```
注意:Spring Cloud 的 `CircuitBreakerFactory` 是**抽象门面**,底下可插 Sentinel 或 Resilience4j,
core/webflux/circuitbreaker 模块演示的就是这层抽象 + Sentinel 实现。

## 8. ⚠️ 全家族注意事项与坑

### 坑 0:parent 链断裂(全家族编译不过的元凶)
6 个模块的 parent 都指向根 pom `com.alibaba.cloud:spring-cloud-alibaba-examples:${revision}`,
而当前根 pom 是 `com.thm.cloud:1.0-SNAPSHOT` 的空壳 → **mvn 编译直接失败**。
修法(与 nacos 家族改造方式一致):把各模块 parent 改为本地链,或在根 pom 补 `${revision}` 属性与
spring-boot / spring-cloud / spring-cloud-alibaba 三大 BOM 的 `dependencyManagement`。

### 坑 1:端口冲突表(和其他家族混跑时注意)

| 端口 | sentinel 模块 | 同仓库撞车 |
|------|---------------|------------|
| 18083 | core | nacos-consumer(18083)、seata-order(18083) |
| 18084 | webflux | seata-account(18084) |
| 18085 | gateway | — |
| 18087 | openfeign | — |
| 18088 | resttemplate | — |
| 80 | circuitbreaker | 常见被本机 IIS/前端工具占用;Windows 上偶发权限问题 |

### 坑 2:count = 0 的语义
QPS 阈值 0 不是"不限流",而是**全部拒绝**。本家族多处故意用 0 演示"一打开就被拦"
(core 的 `/test`、webflux 的 `/mono`、gateway 的参数限流)。自己配规则时千万别手滑。

### 坑 3:熔断 grade 编号新旧不一致
1.8 前后 grade 语义不同(老的 0=RT/1=异常比例;1.8+ 0=慢调用比例/1=异常比例/2=异常数)。
看老博客抄规则前,先确认自己 Sentinel 版本(本仓库 SCA 2023.0.3.2 → Sentinel 1.8.x 新语义)。

### 坑 4:规则默认不持久化
代码 `loadRules()` / 控制台改的规则都在**内存**,重启全丢。文件数据源每次启动重读,
Nacos 数据源可动态推送——生产用 Nacos/Apollo/ZooKeeper 数据源。

### 坑 5:datasource 的 classpath file 在 jar 模式有坑
openfeign / resttemplate 模块 yml 里注释掉的 file 数据源配置,对应官方 issue
(alibaba/spring-cloud-alibaba#3033):classpath 文件数据源在打 jar 运行时读取有问题,
所以这两个模块改成**代码里 loadRules**。json 规则文件在这两个模块里是"参考模板",并未挂载数据源。

### 坑 6:httpbin.org 外网依赖
慢/不可达会误判为"熔断没生效"或"限流有问题",先 `curl https://httpbin.org/get` 验证网络。
