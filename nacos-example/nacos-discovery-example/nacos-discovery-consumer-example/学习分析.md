## 1. 项目定位:它是什么?

这是一个**服务消费者**示例,演示微服务体系中最核心的能力之一:

> **服务 A 如何"找到"并"调用"注册在 Nacos 上的服务 B?**

本项目中:

| 角色 | 服务名 | 说明 |
|------|--------|------|
| **消费者** | `service-consumer`(本项目) | 发起调用的一方,端口 `18083` |
| **提供者** | `service-provider`(需另行运行) | 被调用的一方,**不在本项目中**,需要你自己准备一个服务名为 `service-provider` 的 Provider |

消费者演示了**两种**主流的远程调用方式:

1. **`RestTemplate` + `@LoadBalanced`**(Spring Cloud LoadBalancer 负载均衡)
2. **OpenFeign 声明式调用**(像调本地方法一样调远程接口)

另外项目还包含了 **Sentinel 熔断降级**的雏形配置(但依赖被注释掉了,详见[第 12 节](#12-️-项目中存在的问题与坑重要))。

## 4. 核心概念速览(小白必读)

在阅读代码前,先搞懂这几个词:

### 4.1 Nacos 是什么?
Nacos = **Na**ming and **Co**nfiguration **S**ervice,阿里的开源产品,一个"微服务管家":
- **服务注册**:每个服务启动时把自己的地址(`IP:port`)登记到 Nacos
- **服务发现**:调用方从 Nacos 查询"service-provider 现在有哪些活着的实例"
- 还能做**配置中心**(本项目 nacos-config 模块演示的就是这个)

### 4.2 负载均衡
当 `service-provider` 部署了 3 个实例时,消费者该调用哪一个?
Spring Cloud LoadBalancer 会在客户端把请求**轮询/随机**地分给不同实例。

### 4.3 OpenFeign 声明式调用
不用手写 `restTemplate.getForObject(...)`,只需定义一个接口 + 注解:

```java
@FeignClient(name = "service-provider")
public interface EchoClient {
    @GetMapping("/echo/{str}")
    String echo(@PathVariable("str") String str);
}
```
Spring 会在运行时**自动生成接口的实现(动态代理)**,帮你完成:
`接口方法` → `http://service-provider/echo/xxx` → 负载均衡 → 真实 HTTP 请求

### 4.4 熔断降级
如果 provider 挂了或响应太慢,与其让请求一直卡着,不如**快速失败并返回一个兜底结果**(如 "echo fallback")——这就是降级。

## 5. 启动类分析 ConsumerApplication

📄 `src/main/java/com/thm/cloud/ConsumerApplication.java`

```java
@SpringBootApplication      // Spring Boot 应用标识
@EnableDiscoveryClient      // 开启服务发现:把本服务注册到 Nacos,也能查询其它服务
@EnableFeignClients         // 开启 Feign:扫描 @FeignClient 接口并生成代理对象
@LoadBalancerClients({
        @LoadBalancerClient("service-provider")  // 为指定服务定制负载均衡配置
})
public class ConsumerApplication {
    public static void main(String[] args) {
        SpringApplication.run(ConsumerApplication.class, args);
    }
}
```

**逐个注解读懂:**

| 注解 | 作用 |
|------|------|
| `@EnableDiscoveryClient` | 触发向 Nacos **注册**自己(`service-consumer`),并具备**发现**其它服务的能力。注意:在新版本 Spring Cloud 中此注解其实可省略,只要引入了 Nacos 依赖就会自动注册(自动装配思想)。 |
| `@EnableFeignClients` | 扫描所有 `@FeignClient` 注解的接口(如 `EchoClient`),为每个接口生成动态代理 Bean,可以直接 `@Autowired` 注入使用。 |
| `@LoadBalancerClients` | 按"服务名"精细化配置负载均衡器。这里对 `service-provider` 单独指定了负载均衡配置。⚠️ 注意:`@LoadBalancerClient` 的 `name` 属性值默认会被当作**配置类的名字前缀**使用,详见第 12 节的坑 3。 |

      transport:
        dashboard: localhost:8080   #    Sentinel 控制台地址
      eager: true                   #    启动即初始化(懒加载关闭)
      datasource:
        ds1:
          file:
            file: classpath:flowrule.json    # 流控规则文件
            data-type: json
            rule-type: flow
        ds2:
          file:
            file: classpath:degraderule.json # 熔断规则文件
            data-type: json
            rule-type: degrade

server:
  port: 18083                       # ⑦ 本服务监听端口

management:
  endpoints:
    web:
      exposure:
        include: '*'                # ⑧ 暴露所有 Actuator 端点(/actuator/*)

- `spring.application.name`:服务名,是 Nacos 服务发现的**唯一标识**

- `server.port`:消费者自己的端口

## 7. 两种远程调用方式

### 7.1 方式一:`RestTemplate` + `@LoadBalanced`

📄 `configuration/RestTemplateConfiguration.java`

```java
@Configuration
public class RestTemplateConfiguration {

    @LoadBalanced
    @Bean
    public RestTemplate urlCleanedRestTemplate() {
        return new RestTemplate();
    }

    @LoadBalanced
    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}
```

**核心魔法 —— `@LoadBalanced`:**

普通 `RestTemplate` 无法识别 `http://service-provider` 这种**服务名 URL**(它不是合法域名)。
加上 `@LoadBalanced` 后,Spring 会给这个 RestTemplate 加一个拦截器,流程变成:

```
请求 http://service-provider/echo/hi
        ↓ 拦截器截获
① 向 Nacos 查询 service-provider 的实例列表(如 192.168.1.10:8081、192.168.1.11:8082)
② LoadBalancer 按策略选一个实例
③ 把 URL 替换成 http://192.168.1.10:8081/echo/hi
④ 发出真实请求
```

使用方式(`TestController` 中):

```java
private static final String SERVICE_PROVIDER_ADDRESS = "http://service-provider";

@GetMapping("/echo-rest/{str}")
public String rest(@PathVariable String str) {
    return urlCleanedRestTemplate.getForObject(SERVICE_PROVIDER_ADDRESS + "/echo/" + str, String.class);
}
```

> 💡 被注释掉的 `@SentinelRestTemplate` 注解:原本配合 Sentinel 对 RestTemplate 调用做限流/熔断,因 Sentinel 依赖被注释而禁用。

### 7.2 方式二:OpenFeign 声明式调用(推荐)

📄 `feign/EchoClient.java`

```java
@FeignClient(name = "service-provider", contextId = "service-provider")
public interface EchoClient {

    @GetMapping("/echo/{str}")
    String echo(@PathVariable("str") String str);       // → GET http://service-provider/echo/{str}

    @GetMapping("/divide")
    String divide(@RequestParam("a") Integer a,
                  @RequestParam("b") Integer b);         // → GET http://service-provider/divide?a=..&b=..

    default String divide(Integer a) {                   // default 方法依然是远程调用 divide(a, 0)
        return divide(a, 0);
    }

    @GetMapping("/notFound")
    String notFound();                                   // → GET http://service-provider/notFound
}
```

**注解细节:**
- `name = "service-provider"`:目标服务名,Feign 会自己去 Nacos 解析这个服务名
- `contextId`:Bean 的唯一标识。当**同一个服务名**需要定义**多个** FeignClient 接口时,必须用 contextId 区分,否则启动报 Bean 冲突
- `@GetMapping/@PathVariable/@RequestParam`:与 Spring MVC 写法完全一致,学习成本低,这也是 Feign 流行的原因

**降级类:** 📄 `feign/EchoClientFallback.java`

```java
public class EchoClientFallback implements EchoClient {
    @Override
    public String echo(String str)  { return "echo fallback"; }

    @Override
    public String divide(Integer a, Integer b) { return "divide fallback"; }

    @Override
    public String notFound()        { return "notFound fallback"; }
}
```

当远程调用失败(服务挂了/超时/熔断器打开)时,返回这些兜底文案,而不是让用户看到 500 错误。
⚠️ 但目前这个 Fallback **并没有真正接上**,原因见[第 12 节坑 2](#12-️-项目中存在的问题与坑重要)。

### 7.3 服务发现 API 直查

📄 `TestController.java` 中还有两个"解剖"接口,能直接看到 Nacos 里注册了什么:

```java
@GetMapping("/services")                       // 列出 Nacos 中所有服务名
public Object services() { return discoveryClient.getServices(); }

@GetMapping("/services/{service}")             // 查看某服务的所有实例(ip、port、元数据)
public Object client(@PathVariable String service) { return discoveryClient.getInstances(service); }
```

`DiscoveryClient` 是 Spring Cloud 提供的**服务发现抽象接口**,底层由 Nacos 实现注入。这两个接口非常适合初学者调试观察。

## 8. Sentinel 熔断降级相关代码

### 8.1 UrlCleaner —— 资源名清洗器

📄 `configuration/UrlCleaner.java`

> 🔍 **初学者常见疑问:这个类只是个普通类,没加 @Component/@Bean,谁在调用它?在哪里清洗 URL?**
>
> 答案:接线点在 `RestTemplateConfiguration.java` **被注释掉的注解**里:
> ```java
> // @SentinelRestTemplate(urlCleanerClass = UrlCleaner.class, urlCleaner = "clean")
> ```
> `urlCleanerClass` 指定类、`urlCleaner` 指定方法名。Sentinel 会给这个 RestTemplate 织入拦截器,
> 每次请求前**反射调用** `UrlCleaner.clean(url)` 完成清洗——所以它不需要注册为 Spring Bean。
> 由于注解和 Sentinel 依赖都被注释,当前 UrlCleaner 是**永远不会执行的死代码**,
> 想启用需:① 放开 pom 里的 Sentinel 依赖 ② 放开该注解;验证方法:调用后看日志输出 `enter urlCleaner`。

```java
public class UrlCleaner {
    public static String clean(String url) {
        if (url.matches(".*/echo/.*")) {
            url = url.replaceAll("/echo/.*", "/echo/{str}");  // /echo/abc → /echo/{str}
        }
        return url;
    }
}
```

**为什么需要它?**
Sentinel 以"资源名"为维度做统计限流。如果不清洗:
- `/echo/abc`、`/echo/xyz`、`/echo/123` 会被当成 **3 个不同资源**,各自独立统计,限流规则形同虚设。
清洗后统一归并为 `GET:http://service-provider/echo/{str}` **一个资源**,规则就能覆盖所有 echo 请求。

这个类本来通过 `@SentinelRestTemplate(urlCleanerClass = UrlCleaner.class, urlCleaner = "clean")` 挂到 RestTemplate 上(现在被注释)。

## 9. 规则文件 flowrule.json / degraderule.json

### 9.1 流控规则 flowrule.json

```json
[
  {
    "resource": "GET:http://service-provider/echo/{str}",  // 资源名(和 UrlCleaner 清洗后的名字对应!)
    "controlBehavior": 0,   // 0=快速失败(超出阈值直接拒绝)
    "count": 1,             // QPS 阈值 = 1,超过 1 QPS 就限流
    "grade": 1,             // 1=按 QPS 限流(0=按并发线程数)
    "limitApp": "default",  // 针对所有调用方
    "strategy": 0           // 0=直接限流
  }
]
```

**效果**:对 provider 的 echo 接口,**1 秒内超过 1 次请求就会被 Sentinel 拦截并走降级**。

### 9.2 熔断规则 degraderule.json

```json
[
  { "resource": "GET:http://service-provider/test",  "count": 0.5, "grade": 1, "timeWindow": 30 },
  { "resource": "GET:http://service-provider",       "count": 0.5, "grade": 1, "timeWindow": 10 },
  { "resource": "GET:http://service-provider/sleep", "count": 20.0, "grade": 0, "timeWindow": 30 },
  { "resource": "GET:http://service-provider/divide","count": 0.5, "grade": 1, "timeWindow": 30 }
]
```

| 字段 | 含义 |
|------|------|
| `grade: 1` | 慢调用比例策略 |
| `grade: 0` | 异常比例策略 |
| `count` | 阈值(慢调用比例 0.5 = 50%;grade=0 时 20.0 表示 100% 异常,即全部异常才熔断) |
| `timeWindow` | 熔断时长(秒),熔断期间请求直接走降级,过后半开试探恢复 |

## 10. 一次请求的完整流程图

以 `GET http://localhost:18083/echo-feign/hi` 为例:

```
浏览器/HTTP客户端
      │
      ▼
┌──────────────────────────────────────────────┐
│ 消费者 service-consumer (18083)                │
│                                              │
│  TestController.echo-feign/{str}             │
│      │                                       │
│      ▼                                       │
│  EchoClient (Feign 动态代理)                  │
│      │  目标: service-provider                │
│      ▼                                       │
│  [Sentinel 检查(若启用): 资源 GET:http://     │
│   service-provider/echo/{str} 是否超QPS?]     │
│      │ 超过 → 直接返回 "echo fallback"        │
│      ▼ 通过                                  │
│  LoadBalancer: 向 Nacos 拉取实例列表并选一个   │──── ① ────► ┌─────────────┐
│      │                                       │             │    Nacos     │
│      ▼                                       │      ◄──── ② │ 127.0.0.1   │
│  HTTP GET http://<实例IP:port>/echo/hi        │             │  :8848       │
└──────────────────────────────────────────────┘             └─────────────┘
      │                                                              ▲
      ▼                                                              │
┌──────────────────────────────────────────────┐        ③ 提供者启动时 │
│ 提供者 service-provider (需自行准备)           │ ─────── 注册自己 ──┘
│ 返回 "hello Nacos Discovery hi" 之类响应       │
└──────────────────────────────────────────────┘
      │
      ▼
若调用失败/被限流 → EchoClientFallback.echo() → 返回 "echo fallback"
```

① ② ③:Nacos 的核心职责 —— **注册**与**发现**。

## 11. 如何运行与测试

### 前置条件

1. **启动 Nacos Server**(默认 `127.0.0.1:8848`)
   ```bash
   # Nacos 2.x 单机模式
   sh startup.sh -m standalone     # Linux/Mac
   startup.cmd -m standalone       # Windows
   ```
   默认账号密码 `nacos/nacos`(与 yml 中一致)。

2. **准备一个 service-provider**(本仓库中没有提供 Provider 工程!)
   简单做法:新建一个 Spring Boot 服务,注册到 Nacos、服务名为 `service-provider`,暴露:
   - `GET /echo/{str}`、`GET /divide?a=&b=`、`GET /notFound`、`GET /test`、`GET /sleep`

### 启动消费者

```bash
cd nacos-discovery-example/nacos-discovery-consumer-example
mvn spring-boot:run
```

> ⚠️ 启动前必须先修复第 12 节的编译错误(坑 1),否则编译都过不了。

### 验证与实验

```bash
# 查看注册的服务(确认 provider/consumer 都在)
curl http://localhost:18083/services
# → ["service-provider", "service-consumer", ...]

# 查看实例详情
curl http://localhost:18083/services/service-provider

# RestTemplate 方式调用
curl http://localhost:18083/echo-rest/hello

# Feign 方式调用
curl http://localhost:18083/echo-feign/hello
curl "http://localhost:18083/divide-feign?a=10&b=2"
curl http://localhost:18083/divide-feign2?a=10      # default 方法演示

# Actuator 健康检查
curl http://localhost:18083/actuator/health
```

**推荐实验:把 provider 停掉**,再调用 `echo-feign` 和 `echo-rest`,观察错误现象,理解"为什么需要降级"。

## 12. ⚠️ 项目中存在的问题与坑(重要)

> 这些问题本身也是绝佳的学习材料!建议边看边思考,再对照修复方案。

### 坑 1:编译错误 —— TestController 的 import 包名不对 ❌

`TestController.java` 第 20 行:

```java
import com.alibaba.cloud.examples.feign.EchoClient;   // ❌ 错误!
```

但项目里 `EchoClient` 实际位于 `com.thm.cloud.feign` 包。这是从官方示例拷贝改名时的残留,**直接导致编译失败**。

**修复:**
```java
import com.thm.cloud.feign.EchoClient;   // ✅
```

### 坑 2:Feign 降级(Fallback)实际上没有生效 ⚠️

三个环环相扣的原因:

1. **`@FeignClient` 没有声明 fallback**:
   ```java
   @FeignClient(name = "service-provider", contextId = "service-provider")
   // 缺少 fallback 属性,也没有 configuration = FeignConfiguration.class
   ```
2. **`FeignConfiguration` 类没有 `@Configuration`**,也没有被任何地方引用 —— 里面的 `@Bean` 根本不会注册进容器。
3. **Sentinel 依赖在 pom.xml 中被注释掉了**,而 `feign.sentinel.enabled: true` 依赖 Sentinel;`EchoClientFallback` 要生效也必须走 Sentinel 整合(Spring Cloud OpenFeign 原生不支持 fallback 属性,除非引入 Sentinel)。

**想要降级真正生效的修复三件套:**

```xml
<!-- ① pom.xml 放开 Sentinel 依赖 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
    <version>2023.0.3.2</version>
</dependency>
```

```java
// ② 启用 FeignConfiguration(加 @Configuration,注意它不能被包扫描进主上下文,
//    否则全局生效;标准做法是不加注解,只在 @FeignClient 里引用)
@FeignClient(
    name = "service-provider",
    contextId = "service-provider",
    configuration = FeignConfiguration.class,        // 引用配置
    fallback = EchoClientFallback.class              // 指定降级类
)
public interface EchoClient { ... }
```
> 说明:配置好 ① 和 ② 中的 `fallback` 属性即可;yml 中的 `feign.sentinel.enabled: true` 已写好,加上 Sentinel 依赖后就会生效。

### 坑 3:`@LoadBalancerClient` 的用法值得推敲 ⚠️

```java
@LoadBalancerClients({
        @LoadBalancerClient("service-provider")
})
```

`@LoadBalancerClient` 通常用来为某个服务**指定自定义负载均衡配置**,标准用法是:

```java
@LoadBalancerClient(name = "service-provider", configuration = MyLbConfig.class)
```

当前写法只给了服务名、没给 configuration,**基本等于没配置**,可以安全删掉,或改造成自定义策略:

```java
public class MyLbConfig {
    @Bean
    public ReactorLoadBalancer<ServiceInstance> randomLoadBalancer(
            Environment env, LoadBalancerClientFactory factory) {
        String name = env.getProperty(LoadBalancerClientFactory.PROPERTY_NAME);
        return new RandomLoadBalancer(
            factory.getLazyProvider(name, ServiceInstanceListSupplier.class), name);
    }
}
```

### 坑 4:版本管理不规范 ⚠️

依赖版本全部硬编码在子 pom 中,且缺少 `spring-cloud`、`spring-cloud-alibaba` 的 BOM。多人协作或升级时会非常痛苦。建议父 pom 引入:

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-dependencies</artifactId>
            <version>2023.0.3</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>com.alibaba.cloud</groupId>
            <artifactId>spring-cloud-alibaba-dependencies</artifactId>
            <version>2023.0.3.2</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

### 坑 5:Sentinel 相关配置当前是"摆设" ⚠️

`application.yml` 里的 sentinel 配置(dashboard、flowrule.json、degraderule.json)、被注释的 `@SentinelRestTemplate`、`UrlCleaner` 类——这一整套目前都不工作,因为 Sentinel 依赖被注释了。如果你只学"Nacos 服务发现 + Feign 调用",可以暂时无视它们;如果要学 Sentinel,按坑 2 的步骤先放开依赖。

## 13. 知识点总结与进阶练习

### 本项目覆盖的知识点

- ✅ Nacos 服务注册与发现(`@EnableDiscoveryClient` + yml 配置)
- ✅ `RestTemplate` + `@LoadBalanced` 客户端负载均衡
- ✅ OpenFeign 声明式远程调用(`@FeignClient`、`@EnableFeignClients`、contextId)
- ✅ Feign 接口中的 `default` 方法(仍然是远程调用)
- ✅ `DiscoveryClient` API 查询服务与实例
- ✅ Sentinel 规则文件(流控 grade=1 QPS / 熔断 grade=0 异常比例)——配置已备好,依赖待启用
- ✅ Sentinel 资源名清洗思想

### 推荐动手练习(由浅入深)

1. **修好坑 1**,让项目能跑起来,完成第 11 节全部 curl 验证
2. **自己写一个 provider**(服务名必须是 `service-provider`),部署两个实例(不同端口),观察 `/services/service-provider` 返回两个实例,并多次调用 `/echo-rest/xxx` 验证轮询负载均衡
3. **杀掉一个 provider 实例**,再观察实例列表变化(体会 Nacos 心跳剔除机制)
4. **放开 Sentinel 依赖,接通 Fallback**(坑 2),然后:
   - 疯狂刷 `echo-feign` 接口(>1 QPS),看是否返回 `echo fallback`(验证 flowrule 的 QPS=1 限流)
   - 让 provider 返回 404,观察 `notFound-feign` 的降级行为
5. **进阶**:把 `@LoadBalancerClient` 改成自定义随机策略(坑 3 的示例代码)
6. **进阶**:对比本项目与 `nacos-config` 模块,理解 Nacos 的两大职能:注册中心 vs 配置中心

### 一句话总结

> 本项目演示了微服务消费者的标准姿势:**Nacos 找服务,LoadBalancer 挑实例,RestTemplate/Feign 发请求,Sentinel 兜底**。当前代码中 Sentinel 与降级部分是"预留未启用"状态,且存在一处编译错误,修复它本身就是最好的练习。
