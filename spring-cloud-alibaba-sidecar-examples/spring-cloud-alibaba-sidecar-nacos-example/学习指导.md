# 学习指导：spring-cloud-alibaba-sidecar-nacos-example

> 本模块是 Spring Cloud Alibaba Sidecar 的**主示例**：
> 用 Nacos 作注册中心 + Spring Cloud Gateway 作流量入口，
> 把一个 Node.js 异构服务（`node-service`，端口 8060）"接入" Spring Cloud 微服务生态。

---

## 一、这个模块做了什么

用一个 30 行代码的 Java 壳应用（`DemoApplication` + `application.yml`），
**代替本机 Node.js 服务去 Nacos 注册中心"报到"**，让整个 Spring Cloud 集群
可以把一个非 Java 服务当成普通 Java 微服务来发现和调用。

### 核心组成（本模块只有 3 个文件）

| 文件 | 作用 |
|---|---|
| `DemoApplication.java` | 启动类，仅多了 `@LoadBalancerClients({@LoadBalancerClient("node-service")})` 声明负载均衡客户端 |
| `application.yml` | 全部魔法所在：sidecar 三行配置 + nacos 地址 + gateway 路由开关 |
| `../node-service.js` | 被接入的"异构服务"：Node.js HTTP 服务，监听 8060，提供 `/` 和 `/health.json` 两个接口 |

### 工作原理（重要：理解流量路径）

```
Java Sidecar 应用(8070) ──注册──► Nacos(8848)
        注册信息: name=node-service, ip=127.0.0.1, port=8060
        ★ 注册的是 Node 的地址，流量不经过 sidecar 进程！

其他 Java 服务/网关 ──lb://node-service──► 127.0.0.1:8060 (直达 Node.js)
```

Sidecar 承担两个职责：
1. **注册代理**：启动时以 Node 服务的 IP/端口注册到 Nacos；
2. **健康哨兵**：定期请求 `health-check-url`，Node 挂了就通知 Nacos 下线该实例。

### 关键配置逐行解读（application.yml）

```yaml
spring.application.name: node-service   # 注册到 Nacos 的服务名（和 Node 服务同名）
sidecar.ip: 127.0.0.1                   # 异构服务的 IP
sidecar.port: 8060                      # 异构服务的端口
sidecar.health-check-url: ...           # 健康检查地址（不配默认 UP）
spring.cloud.gateway.discovery.locator.enabled: true  # 网关按服务名自动建路由
spring.cloud.loadbalancer.nacos.enabled: true         # 负载均衡器适配 Nacos
```

依赖方面（pom.xml）：`sidecar` + `nacos-discovery` + `gateway` + `loadbalancer` + `actuator`。

## 二、需要学习的知识点

1. **Sidecar 模式思想**（Sidecar Pattern）
   - 为什么不改写老服务也能融入微服务治理；
   - 区别于 Istio/Envoy 的"流量代理"型 Sidecar，SCA Sidecar 是"**注册代理**"——转发注册与心跳，不转发业务流量。
2. **Nacos 服务注册与发现**
   - 服务名、分组（group=test）、实例 IP/端口、元数据；
   - 控制台（localhost:8848/nacos）查看服务列表与健康状态。
3. **Spring Cloud Gateway 的服务发现路由**
   - `discovery.locator.enabled: true` 如何实现按服务名自动路由；
   - 访问 `http://127.0.0.1:8070/node-service/health.json` 的转发链路。
4. **Spring Cloud LoadBalancer**
   - `@LoadBalancerClient("node-service")` 注解的作用与自定义空间；
   - Nacos 负载均衡适配（`loadbalancer.nacos.enabled`）。
5. **健康检查机制**
   - 健康返回 JSON 的格式要求：`{"status":"UP"}` / `{"status":"DOWN"}`；
   - 健康状态如何影响 Nacos 实例上下线。
6. **Actuator 监控**
   - `management.endpoint.health.show-details: always` 查看 sidecar 自身健康。

## 三、学习目的

- **理解异构语言微服务治理方案**：公司里 Node/Python/Go 老服务与 Java 微服务并存是常态，掌握 Sidecar 就掌握了"零侵入接入"的钥匙；
- **吃透注册中心的本质**：注册中心只认"服务名 + IP + 端口 + 健康状态"，不关心实现语言——这是微服务互通的底层逻辑；
- **掌握 Gateway + LoadBalancer 联动**：这是 Spring Cloud 内服务间调用的标准姿势，属于通用核心能力。

## 四、以后怎么用（实战场景）

1. **老系统渐进式改造**：Python 算法服务、Node BFF 层不用重写，套一个 Sidecar 壳即可被 Java 网关统一路由、被 Feign 直接调用；
2. **多语言技术团队协作**：不同语言团队各自维护服务，Java 团队用 Sidecar 把它们纳入统一注册/发现/监控体系；
3. **接入姿势（三步）**：
   - Step1：引入 `spring-cloud-starter-alibaba-sidecar` + `nacos-discovery` + `gateway`；
   - Step2：yml 配置 `sidecar.ip/port/health-check-url`，`application.name` 设为异构服务名；
   - Step3：异构服务实现一个返回 `{"status":"UP|DOWN"}` 的健康接口，启动 sidecar 应用即完成接入。
4. **生产建议**：
   - Sidecar 与异构服务**同机部署**（同 Pod/同主机），网络延迟可忽略；
   - health-check-url 必须配置（不配默认 UP，节点故障不会摘除，有雪崩风险）；
   - 用 systemd/K8s 把 sidecar 进程与异构服务生命周期绑定。

## 五、动手验证清单

- [ ] 启动 Nacos（`startup.cmd -m standalone`），浏览器登录 localhost:8848/nacos；
- [ ] `node node-service.js` 启动异构服务（8060）；
- [ ] 启动本模块 `DemoApplication`（8070）；
- [ ] Nacos 控制台看到 `node-service`（group=test）注册成功；
- [ ] 访问 `http://127.0.0.1:8070/node-service/health.json` 返回 `{"status":"UP"}`；
- [ ] 把 node-service.js 中健康返回改为 `DOWN`，观察 Nacos 中实例被标记为不健康；
- [ ] 再写一个 Java 服务用 `Feign/LoadBalancer` 调用 `node-service`，验证与调 Java 服务无差别。
